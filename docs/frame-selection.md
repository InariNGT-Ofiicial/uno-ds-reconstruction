# 怎样决定哪些帧要画

## 三种“帧数”必须分开

本地参考是24 fps、5245帧。这个数是解码与事件定位的时间轴。成片仍用24 fps编码，让同一张核心稿曝光多帧。它不等于需要生成5245张图。

0.25秒一张的联系表是导航，也不等于生产时固定每秒4张。用户先提过4 fps，随后明确改成“保存动作切换的关键帧，去掉连接帧”。最终流程以后者为准。

176个连续时间区间也不是176张独立原画：一个人物稿可因嘴型、字幕、镜头单位、纯图形或安全原片模式而对应不同事件区间。当前实际使用83个完整画面文件，里面仍包含净版和表情变体。

## 第一遍：建立可回查的源时间坐标

`tools/catalog_source.py` 按解码顺序保存：

- 零起始的帧号、原 PTS 与 time base；
- 解码 RGB 像素 SHA256；
- 142 × 80 缩略图的相邻帧平均绝对差与变化像素比例；
- 32 × 18 灰度平均哈希；
- 2秒、0.25秒两级联系表，以及低分辨率全率缓存。

精确像素相同可以证明该输入栅格一致。像素不同却不能直接证明姿态不同：压缩噪声、相机推近、文字和遮挡都会改变像素。平均差和感知哈希因此只用于找候选，不用于自动判定该省哪张手。

所有区间用 `[start_frame, end_frame_exclusive)`。例如 `[854,866)` 保留12帧曝光，下一状态从866开始，避免首尾重叠或漏一帧。

## 第二遍：找动作家族，复查切点

先从联系表建立镜头导航和候选姿态，再打开候选附近的原帧率画面。需要保留的通常是：

| 保留项 | 本片例子 |
|---|---|
| 新手势或接触关系 | 牌从一只手换到另一只手；张手随之换边 |
| 明确方向反转或极点 | 双 V 指向两侧倾头的交替极点 |
| 起势、落定 | 坐正空手 → 侧背压低 → 正前俯身 |
| 持续的表情状态 | 无眼红影、左右瞟眼、闭眼小笑、咬牙嘴 |
| 镜头／服装变化 | 原 MV 自身的女仆插入镜头 |

小幅连接抖动、极短的进入姿态、同一动作之间的普通过渡可以由前一核心稿承接。这个判断必须看动作语义，不能把“我们已经有一张类似图”作为省略理由。

## 第三遍：安排真实曝光，不均分时间

33–38秒的修订是一个具体例子。以下帧号指完整原片，不是局部小样的帧号：

| 源区间 | 采用稿 | 为什么 |
|---|---|---|
| `[812,854)` | 828 | 双 V 手进入后的第一相位；从入口直接使用新家族，避免切回旧发型稿 |
| `[854,866)` | 858 | 一侧倾斜极点 |
| `[866,879)` | 870 | 反方向倾斜极点 |
| `[879,894)` | 同一份858 | 原动作再次返回，复用同一文件 |
| `[894,904)` | 同一份870 | 第二次方向反转 |
| `[904,944)` | 912 | 小 O 嘴转为抖动笑嘴；延续到该镜头结束，不在38秒整点突然退回旧稿 |

这里的828、858、870、912是用于画稿的源代表帧；曝光切点可以早于代表帧。不能拿代表帧索引均分区间，也不能把858提前到尚未倾头的源相位。

102–106秒也采用同样口径：2447–2458的无眼红影不能用半睁眼远景替代；2458、2476、2499、2521的瞟眼相位分别安排已通过的两张稿；2544转入更近的慌张状态；2550咬牙嘴出现后使用2568代表稿，直到2582切镜。

## 复用之前检查什么

相同角色、相同屏幕侧或相同头朝向，都不足以证明身体原画相同。原先把1560和1620归入旧嘲讽母稿，漏掉了两手的牌与 V 手交换，后续必须新画整姿态。

复用成立后，直接引用同一个已通过的文件和 SHA256。不要为了“变化一点”再生成一张相似图。嘴型和气泡更新在独立事件表里完成。

原片绿色头发的质心曾用于只读分析，帮助判断画面左右相位。这个分类特征不是生产用的初音发型蒙版，也不会把原人物像素粘进新稿。

## 最后一遍专门找过度省略

第一次全片整合只解决了覆盖，仍漏掉了手部外摆、女仆合爪、空手坐正和持续表情。我们因此反查：

1. 单稿长停格期间，原片是否还有清楚可读的新手势？
2. 所有别名是否把“相同侧面”误当作“相同身体”？
3. 两次副歌的重复段是否真的同姿态、同时间偏移？
4. 源动作切换是否发生在导航网格之前？例如首次女仆插入从1886开始，而不是导航候选1896。
5. 主体、嘴、字卡和遮挡是否误绑成一个时钟？

实际发现、原帧证据引用与修订状态见 [action-key-review.json](../evidence/action-key-review.json)。它是历史审计，不能脱离当前修订规则阅读。

## 当前版本的明确例外

原片开场确实存在 A/B 招手曝光。用户在最后一轮明确要求“开头两帧用一帧就好”，所以 `[31,145)` 最终全部使用 `intro_palm_open`。这项人工取舍优先于历史报告中的恢复 A/B 建议，见 [revision-v3-plan.json](../project/revision-v3-plan.json)。不能为了追求自动“保留全部切换”，又擅自把开场 A/B 恢复回来。

## 编译与验收

`tools/build_plan.py` 把候选镜头、通过稿、嘴型事件和显式修订编译为当前时间线。未分类、缺通过稿、覆盖重叠、时间不单调或长时间残留烘焙字幕都应报错，而不是拿原初音人物画面填空。

`tools/validate_project.py` 检查连续覆盖和资源哈希。它不会替代语义审计：一张五指手错误变成四指、牌换了持有手，或明明该闭眼却一直睁眼，仍需对照真实原帧。
